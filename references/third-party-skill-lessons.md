# 第三方 HTML 技能踩坑清单

本文件整理自对一批公开第三方 HTML 技能的逐个实测与拆包：哪些做法值得吸收，哪些坑在自己产出时要主动绕开。核心原则：**技能文档声称的能力，交付前逐项核对；环境与依赖不默认存在；材料为空先查原因，不拿占位内容凑版面。**

## 1. 脚本路径不能写死本机绝对路径

**坑**：截图、导出、拉取数据的脚本里，输入输出目录写成某台机器上的绝对路径（如 `/Users/xxx/skills/...`、`C:\Users\xxx\...`），换一台机器直接跑不起来；说明里却写「环境已装好，无需安装」。

**做法**：

- 路径全部参数化：命令行参数、环境变量或相对路径，脚本内不出现他人用户名目录。
- 交付前在干净目录跑一遍导出/截图链路，确认不依赖本机残留文件。
- 说明里的环境声明要逐项核对（依赖是否安装、目录是否存在），不照抄上游说法。

## 2. 文档声称的图表/流程图库，可能没随包提供

**坑**：技能说明写「支持流程图、支持某图表库」，翻遍目录找不到对应文件；照说明做，流程图区块最后变成一段代码原样躺在页面上。

**做法**：

- 动笔前核对文档引用的库、模板、脚本是否真的在包里；缺文件就按缺失能力处理，不假装支持。
- 零依赖约束下，图表降级为内联 SVG 或纯 CSS 绘制；流程图用 SVG 节点 + 连线，不贴裸代码。
- 交付说明里标明哪部分能力不可用、为什么，不把未验证的能力写进承诺。

## 3. 安装失败先核对目标目录与安装器清单

**坑**：市场里能搜到技能，点安装却回「不在可安装目录里」；部分技能根本没放进安装器支持的目录。

**做法**：

- 安装前先跑安装器的 `--list`，确认目标助手目录在清单内。
- 技能目录结构必须是 `<技能目录>/SKILL.md`，多套一层目录应用就扫不到。
- 公开库收录时，许可未核实的第三方技能只记录入口与教训，不放正文。

## 4. 摘录/笔记为空，先查登录态与请求条件

**坑**：笔记、划线、书评区块渲染为空，容易被当成内容正常、版面留白；实际是登录态失效、cookie 过期或请求缺少必要的 Referer/编码标识。

**做法**：

- 材料为空时先排查：登录态是否有效、cookie 是否新鲜、请求头是否齐全（如阅读器页面的 Referer、内容编码标识）。
- 确认账号在浏览器里能读到内容、导出却为空时，优先怀疑请求条件，而不是补写内容。
- 排查后仍为空，如实报告「当前材料没有可整理的摘录」，不生成占位金句。

## 5. 导出 PDF/图片：本地图片走相对路径，经本地服务加载

**坑**：导出脚本用绝对文件路径引用本地图片，无头浏览器读不到；截图后图块缺失。

**做法**：

- HTML 内图片用相对路径，导出时起本地 HTTP 服务托管父目录，再由无头浏览器加载。
- 需要单文件传阅时，图片 base64 内嵌进 HTML，避免路径依赖。
- 文件名尽量不用空格；出现空格由脚本编码处理，不手动假设浏览器行为。

## 6. 数据与口径：数字来自输入，假设写进方法论区

**坑**：报告里出现估算的占位数字、口径前后不一；同比环比算不出来却照常展示。

**做法**：

- KPI、图表、表格只用用户提供或可从输入算出的数字；缺失值如实标注，不补造。
- 统计口径、时间区间、假设与缺失值处理方式，集中写进文末方法论折叠区（`<details>`）。
- 洞察结论必须能对应到具体指标；数据支持不到的因果，标为待验证，不写成定论。

## 7. 中文排版：按字宽留空间，不靠 emoji 当图标

**坑**：中文长标题在卡片里错行、贴边、溢出；用 emoji 充当功能图标，不同设备渲染成豆腐块或彩色杂块。

**做法**：

- 全角汉字按字号计宽预留文本盒宽度，盒内四周留内边距；长词允许换行，盒高随之预留。
- 功能图标用内联 SVG 绘制；彩色圆点用矢量形状画，不用 emoji 顶替。
- 中英混排留盘古之白；小字投屏不可读时优先减文字，不靠缩字号硬塞。

## 8. 固定尺寸画布：内容不滚动、图表容器有高度

**坑**：海报/幻灯片页面出现页内滚动；图表库开 `responsive + maintainAspectRatio: false` 时父容器缺高度，布局卡死或图表不渲染。

**做法**：

- 海报/长图内容完整落在目标尺寸内，字号间距保证无溢出。
- 图表容器给固定高度（外层 `position: relative; height: 280px`，迷你趋势线 40–60px）。
- 幻灯片每页一屏，内容溢出就拆页，不在页内滚动。

## 9. 先读材料定结构，再写页面

**坑**：没读完原文就套模板，类比失真、综述补造、摘录与评价混在一起。

**做法**：

- 动笔前先体检材料：主题、原文摘录、个人思考、元信息是否齐全，缺项先问。
- 类比必须贴切，并指出类比在哪里失效；摘录保持原样，综述单独分区。
- 区分「原文」与「我的概括」，归属在版面层级上分得开。

## 10. 出件后核验，不凭感觉说「生成好了」

**坑**：脚本退出码为 0 就报告完成，实际 PDF 没更新、图片丢失、关键词提取不全。

**做法**：

- 核验页数、关键词是否命中、关键图是否渲染；把首页与最密的一页表格渲染成图目检。
- 目标 PDF 被预览器占用时可能静默失败：比对源文件与产物的修改时间，源新而产物没变就是被锁。
- 保留源 HTML/源数据，改文案后重跑一条命令即可重出产物，不要只留成品。

## 来源与边界

以上教训来自公开技能评测记录与拆包观察；上游技能名在许可未核实时不逐条署名，具体归类与做法已改写进本库对应技能与参考文件。本清单只约束自己产出时的检查项，不构成对任何上游技能完整性或可用性的担保。
